# Learning curriculum: Frontend Developer

Build an accessible browser interface before introducing frameworks.

[Home](../README.md) / [Curricula](curricula.md) / [Software, interfaces and embedded systems](professions-software.md#roles-in-this-group)

**Target profile:** [Frontend Developer](professions-software.md#frontend-developer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic file skills
- A browser and text editor

**What you will produce:** A responsive study planner with keyboard-operable controls and a browser test.

**Resource coverage:** 4 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Structure a task interface](#stage-1)
2. [Adapt the layout](#stage-2)
3. [Handle state and events](#stage-3)
4. [Deliver the interface mini-project](#stage-4)

<a id="stage-1"></a>
## 1. Structure a task interface

**Learn:**

- Semantic HTML
- Labels and forms

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [MDN Web Docs](https://developer.mozilla.org/) — all in this topic; free access. [Details](area-web.md#resource-mdn-web-docs).

**Practise:** Create a planner page with headings, a labelled task field and a task list.

**Advance when:** Reach and submit the form using only the keyboard and explain its document structure.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Adapt the layout

**Learn:**

- CSS layout
- Responsive design
- Visible focus

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [web.dev Learn](https://web.dev/learn) — beginner in this topic; free access. [Details](area-web.md#resource-web-dev-learn).

**Practise:** Style the planner for narrow and wide windows while preserving visible focus.

**Advance when:** Check both widths without horizontal overflow and reach every control by keyboard.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Handle state and events

**Learn:**

- DOM updates
- Event handlers
- Input validation

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [The Modern JavaScript Tutorial (javascript.info)](https://javascript.info/) — beginner in this topic; free access. [Details](area-web.md#resource-javascript-info).

**Practise:** Add, complete and filter tasks with a small JavaScript state model.

**Advance when:** Demonstrate empty, invalid and populated states without console errors.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the interface mini-project

**Learn:**

- Browser assertions
- Accessibility checks
- Local setup

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Playwright - Getting Started](https://github.com/microsoft/playwright) — intermediate in this topic; free access. [Details](area-testing.md#resource-playwright-getting-started).
- [MDN Web Docs](https://developer.mozilla.org/) — all in this topic; free access. [Details](area-web.md#resource-mdn-web-docs).

**Practise:** Add a browser test for creating a task and document how to run the planner locally.

**Advance when:** Reproduce the task workflow with mouse and keyboard and show the automated result.

## After this recipe

Compare a framework only after explaining the state and events in the interface you can already build.
