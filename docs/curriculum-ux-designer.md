# Learning curriculum: UX Designer

Investigate a user task and improve its interaction using evidence.

[Home](../README.md) / [Curricula](curricula.md) / [Software, interfaces and embedded systems](professions-software.md#roles-in-this-group)

**Target profile:** [UX Designer](professions-software.md#ux-designer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic computer skills
- Ability to obtain consent for a short usability session

**What you will produce:** A task-flow prototype revised after observing a consenting participant.

**Resource coverage:** 4 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Understand one user task](#stage-1)
2. [Model the interaction](#stage-2)
3. [Prototype the critical path](#stage-3)
4. [Deliver the UX revision](#stage-4)

<a id="stage-1"></a>
## 1. Understand one user task

**Learn:**

- Research questions
- Observation
- Consent and notes

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Practice Library](https://github.com/openpracticelibrary/openpracticelibrary) — intermediate in this topic; free access. [Details](area-design-product.md#resource-open-practice-library).

**Practise:** Observe a consenting person organizing fictional study tasks without collecting sensitive data.

**Advance when:** Separate three observations from assumptions and describe the task in plain language.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Model the interaction

**Learn:**

- Task flow
- Information hierarchy
- Alternative approaches

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Practice Library](https://github.com/openpracticelibrary/openpracticelibrary) — intermediate in this topic; free access. [Details](area-design-product.md#resource-open-practice-library).
- [GOV.UK Design System](https://github.com/alphagov/govuk-design-system) — intermediate in this topic; free access. [Details](area-design-product.md#resource-govuk-design-system).

**Practise:** Sketch the existing task flow and two simpler alternatives before polishing visuals.

**Advance when:** Explain how each alternative addresses an observed obstacle.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Prototype the critical path

**Learn:**

- Low-fidelity screens
- Feedback states
- Accessible interactions

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Penpot](https://github.com/penpot/penpot) — beginner in this topic; freemium access. [Details](area-design-product.md#resource-penpot).
- [GOV.UK Design System](https://github.com/alphagov/govuk-design-system) — intermediate in this topic; free access. [Details](area-design-product.md#resource-govuk-design-system).

**Practise:** Create a clickable flow with empty and error states.

**Advance when:** A reviewer can complete the main task and recover from the designed error.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the UX revision

**Learn:**

- Usability observation
- Iteration
- Evidence limits

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Practice Library](https://github.com/openpracticelibrary/openpracticelibrary) — intermediate in this topic; free access. [Details](area-design-product.md#resource-open-practice-library).
- [Penpot](https://github.com/penpot/penpot) — beginner in this topic; freemium access. [Details](area-design-product.md#resource-penpot).

**Practise:** Run a consented task session and deliver before-and-after flows and a decision record.

**Advance when:** Connect each revision to an observation without generalizing one participant to all users.

## After this recipe

Study research methods and accessibility further; a short session is exploratory evidence, not a representative user study.
