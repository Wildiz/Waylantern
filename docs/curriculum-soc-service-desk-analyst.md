# Learning curriculum: SOC Service Desk Analyst

A security request intake and escalation recipe, emphasizing careful communication and useful tickets.

[Home](../README.md) / [Curricula](curricula.md) / [Cybersecurity, audit and risk](professions-security.md#roles-in-this-group)

**Target profile:** [SOC Service Desk Analyst](professions-security.md#soc-service-desk-analyst)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic computer use and clear written communication.

**What you will produce:** A set of sanitized security intake tickets with correct routing, urgency and handoff details.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

<a id="stage-1"></a>
## 1. Recognize requests and security signals

**Learn:**

- Accounts, phishing reports and suspicious activity
- Confidentiality and minimum necessary information

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Professor Messer (CompTIA Network+ and Security+ videos)](https://www.professormesser.com/security-plus/sy0-701/sy0-701-video/sy0-701-comptia-security-plus-course/) — beginner in this topic; free access. [Details](area-devops.md#resource-professor-messer).

**Practise:** Sort six fictional reports into routine support, security review or immediate escalation, explaining each choice.

**Advance when:** Your classifications distinguish observed events from the reporter's interpretation.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Record an actionable ticket

**Learn:**

- Required fields and asset identification
- Timestamps, contact details and sensitive data minimization

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [GLPI](https://github.com/glpi-project/glpi) — intermediate in this topic; free access. [Details](area-it-support.md#resource-glpi).

**Practise:** Use a disposable ticket lab or a local template to record the reports without passwords or real personal information.

**Advance when:** Every ticket names the symptom, time, affected asset, source of the report and missing information.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Route and communicate

**Learn:**

- Escalation criteria and ownership
- Acknowledgement and user-safe instructions

**Resource still needed:** No organization-specific security service-desk procedure has been verified; routing and response expectations here are simulated.

**Practise:** Create an editorial routing matrix for a locked account, a phishing report and a suspected compromised device; draft acknowledgement messages.

**Advance when:** Each route has an owner and an urgent fallback; messages do not ask users to transmit credentials or investigate malware.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Run an intake tabletop

**Learn:**

- Handover completeness and queue review
- Closure evidence and reopening conditions

**Resource still needed:** No assessed SOC service-desk curriculum has been verified; this tabletop tests documentation and coordination only.

**Practise:** Role-play intake for three reports, then hand the tickets to another learner and revise fields they cannot understand.

**Advance when:** The final ticket packet includes complete handoffs, an escalation record and a closure or pending reason for each case.

## After this recipe

Practise under a team's approved intake process, then study SOC investigation if you want responsibility for analyzing the escalated cases.
