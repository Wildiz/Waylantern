# Learning curriculum: IT Support Technician

Resolve a small user problem through safe checks, a reversible fix and a clear support record.

[Home](../README.md) / [Curricula](curricula.md) / [Operations, platforms and IT support](professions-operations.md#roles-in-this-group)

**Target profile:** [IT Support Technician](professions-operations.md#it-support-technician)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Use basic files and applications.
- Have a disposable practice system and fictional user information.

**What you will produce:** A lab support case with user-friendly notes, diagnostic evidence and a verified outcome.

**Resource coverage:** 4 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Understand the user and system](#stage-1)
2. [Run safe operating-system checks](#stage-2)
3. [Make and verify a reversible fix](#stage-3)
4. [Capstone: complete a fictional support ticket](#stage-4)

<a id="stage-1"></a>
## 1. Understand the user and system

**Learn:**

- Plain-language questioning
- Basic hardware and operating-system boundaries

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Professor Messer (CompTIA Network+ and Security+ videos)](https://www.professormesser.com/security-plus/sy0-701/sy0-701-video/sy0-701-comptia-security-plus-course/) — beginner in this topic; free access. [Details](area-devops.md#resource-professor-messer).

**Practise:** Use introductory A+ video material to distinguish device, operating-system and application symptoms in three fictional reports.

**Advance when:** For each report, ask a useful next question and identify a safe first check; videos alone do not count as hands-on practice.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Run safe operating-system checks

**Learn:**

- Files, accounts and permissions
- Service status and logs

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Linux Upskill Challenge](https://github.com/livialima/linuxupskillchallenge) — beginner in this topic; free access. [Details](area-it-support.md#resource-linux-upskill-challenge).
- [PowerShell 101 (Microsoft)](https://github.com/MicrosoftDocs/PowerShell-Docs/tree/main/reference/docs-conceptual/learn/ps101) — beginner in this topic; free access. [Details](area-it-support.md#resource-powershell-101).

**Practise:** On one chosen practice operating system, inspect identity, storage availability and a service without changing the daily-use system.

**Advance when:** Explain the output in plain language and distinguish an observation from a diagnosis.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Make and verify a reversible fix

**Learn:**

- Change records
- Functional user checks

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Microsoft Windows Troubleshooting Documentation](https://github.com/MicrosoftDocs/SupportArticles-docs/tree/main/support/windows-client) — intermediate in this topic; free access. [Details](area-it-support.md#resource-microsoft-windows-troubleshooting).

**Practise:** Choose an applicable Windows case or explicitly documented lab configuration issue, record the current state and test one reversible correction.

**Advance when:** A user-facing check succeeds after the change and the record explains how to undo it; do not apply unrelated article fixes.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Capstone: complete a fictional support ticket

**Learn:**

- User communication
- Evidence and escalation

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [GLPI](https://github.com/glpi-project/glpi) — intermediate in this topic; free access. [Details](area-it-support.md#resource-glpi).

**Practise:** Record the report, checks, correction and functional outcome in a test ticket, or escalate if the evidence remains inconclusive.

**Advance when:** Another reader can see what the user experienced, what changed and why the case was resolved or escalated.

## After this recipe

Choose an operating system and device environment, then gain supervised support practice beyond this small lab.
