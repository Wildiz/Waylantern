# Learning curriculum: Technical Writer

Write and test a small documentation set that helps a defined reader complete a task.

[Home](../README.md) / [Curricula](curricula.md) / [Leadership, product and technology relationships](professions-leadership.md#roles-in-this-group)

**Target profile:** [Technical Writer](professions-leadership.md#technical-writer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Can use files and a browser and explain a small task in plain language.
- Can access a small tool or application to document; coding experience depends on that subject.

**What you will produce:** A tested quickstart, task guide and reference note with a maintenance and review plan.

**Resource coverage:** 3 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

<a id="stage-1"></a>
## 1. Define the reader and the job of the document

**Learn:**

- Audience knowledge
- Task analysis
- Document scope

**Resource still needed:** A verified introductory technical-writing curriculum is not yet catalogued; this exercise defines the learning task but does not replace writing instruction.

**Practise:** Choose a small tool you can use. Write who the reader is, their starting knowledge, the task and the success condition; identify terms that need explaining before use.

**Advance when:** The brief defines a specific task and reader without assuming unexplained jargon.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Write a reproducible task guide

**Learn:**

- Procedural steps
- Expected results
- Error recovery

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [GitHub Skills: Introduction to GitHub](https://github.com/skills/introduction-to-github) — beginner in this topic; free access. [Details](area-software.md#resource-github-skills-introduction-to-github).

**Practise:** Create a simple Markdown guide in a practice repository. State prerequisites, give one action per step, show the expected result and explain recovery from one likely mistake.

**Advance when:** A reader can follow the guide in order and knows how to confirm each critical action.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Separate explanation from reference

**Learn:**

- Conceptual models
- Reference structure
- Consistent terminology

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [MDN Web Docs](https://developer.mozilla.org/) — all in this topic; free access. [Details](area-web.md#resource-mdn-web-docs).

**Practise:** Inspect how the documentation distinguishes a tutorial, explanation and API reference. Apply that distinction to your tool by adding a short concept explanation and a compact reference note.

**Advance when:** The three pieces answer different reader needs and use terms consistently; copying a reference page is not treated as a complete tutorial.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Test and maintain the documentation

**Learn:**

- Reader feedback
- Review workflow
- Version assumptions

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Source Guides](https://opensource.guide/) — beginner in this topic; free access. [Details](area-software.md#resource-open-source-guides).

**Practise:** Ask a willing reader to attempt the task without coaching, or label a solo walkthrough. Revise one observed problem and record which product changes would require a documentation update.

**Advance when:** Your capstone contains a quickstart, task guide, reference note, feedback evidence and a maintenance checklist; untested claims are marked.

## After this recipe

Add a verified writing course when catalogued and practise documentation reviews in the domain you want to explain.
