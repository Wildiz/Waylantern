# Editorial practice plan: iOS Developer

Build a small persistent application with Swift and SwiftUI.

**Target profile:** [iOS Developer](professions-software.md#ios-developer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic computer skills
- Compatible Apple development hardware and Xcode

**What you will produce:** A reading-log prototype with validation, navigation and saved records.

**Resource coverage:** 4 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Write Swift data models](#stage-1)
2. [Create the SwiftUI workflow](#stage-2)
3. [Persist and restore entries](#stage-3)
4. [Deliver the iOS mini-app](#stage-4)

<a id="stage-1"></a>
## 1. Write Swift data models

**Learn:**

- Values and types
- Functions
- Optional values

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Develop in Swift Tutorials](https://developer.apple.com/tutorials/develop-in-swift/) — beginner in this topic; free access. [Details](area-software.md#resource-develop-in-swift).

**Practise:** Follow introductory Swift material and represent a reading-log entry.

**Advance when:** Explain an absent optional value and distinguish it from an empty title.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Create the SwiftUI workflow

**Learn:**

- Views and state
- Navigation
- Form input

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Develop in Swift Tutorials](https://developer.apple.com/tutorials/develop-in-swift/) — beginner in this topic; free access. [Details](area-software.md#resource-develop-in-swift).

**Practise:** Build a book list and a detail form for a reading note.

**Advance when:** Navigate between list and detail without unexpectedly losing unsaved input.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Persist and restore entries

**Learn:**

- Local persistence
- Lifecycle
- Validation

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Develop in Swift Tutorials](https://developer.apple.com/tutorials/develop-in-swift/) — beginner in this topic; free access. [Details](area-software.md#resource-develop-in-swift).

**Practise:** Save the reading log using the tutorial approach and reject invalid entries.

**Advance when:** Restart the simulator and retrieve the saved record while rejecting an empty title.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the iOS mini-app

**Learn:**

- Accessibility labels
- Repeatable checks
- Build instructions

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Develop in Swift Tutorials](https://developer.apple.com/tutorials/develop-in-swift/) — beginner in this topic; free access. [Details](area-software.md#resource-develop-in-swift).

**Practise:** Deliver simulator setup and checks for adding, editing and restoring reading notes.

**Advance when:** A clean build reproduces the workflow and clearly distinguishes simulator from device evidence.

## After this recipe

Study permissions and device testing next and verify platform or publishing costs before choosing distribution.
