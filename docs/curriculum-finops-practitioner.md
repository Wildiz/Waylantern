# Learning curriculum: FinOps Practitioner

Analyse a fictional cloud bill and propose measurable cost decisions with owners and service trade-offs.

[Home](../README.md) / [Curricula](curricula.md) / [Operations, platforms and IT support](professions-operations.md#roles-in-this-group)

**Target profile:** [FinOps Practitioner](professions-operations.md#finops-practitioner)

**Starting point:** Prior practical experience required

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Understand common cloud resource and pricing models.
- Have practical experience discussing service ownership and operational constraints.
- Use spreadsheets or SQL to reconcile totals.

**What you will produce:** A reconciled synthetic spend report, allocation policy, forecast and justified optimisation proposal.

**Resource coverage:** 0 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

1. [Construct a defensible cost model](#stage-1)

<a id="stage-1"></a>
## 1. Construct a defensible cost model

**Learn:**

- Usage units and rates
- Credits and shared charges

**Resource still needed:** No reviewed FinOps cost-management curriculum or current provider price source is catalogued.

**Practise:** Create a fictional bill with compute hours, storage quantities, transfer charges and one credit; state all assumptions.

**Advance when:** The total reconciles with unit rates and no invented number is presented as a current provider price.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Allocate costs to accountable owners

**Learn:**

- Labels and allocation rules
- Shared-cost treatment

**Resource still needed:** A reviewed FinOps allocation and governance guide is missing; the allocation policy is a stated practice assumption.

**Practise:** Assign synthetic charges to two teams and one shared platform, documenting what remains unallocated.

**Advance when:** The allocations sum to the original bill and every shared-charge rule is explained.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Compare optimisation options

**Learn:**

- Forecast uncertainty
- Reliability and commitment risks

**Resource still needed:** No reviewed resource establishes current discount products, purchasing terms or FinOps optimisation standards.

**Practise:** Compare deleting an idle resource, rightsizing and a hypothetical commitment using estimated usage ranges.

**Advance when:** The recommendation includes savings assumptions, break-even conditions and a service-risk owner.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Capstone: present a cost decision

**Learn:**

- Action ownership
- Measurement after change

**Resource still needed:** This is an editorial simulation using fictional prices, not financial advice, a certification syllabus or a reviewed cloud-billing lab.

**Practise:** Prepare a one-page cost review with an allocation chart, forecast range and one proposed action with a follow-up date.

**Advance when:** A stakeholder can identify the baseline, approved action, expected saving and evidence that would invalidate it.

## After this recipe

Use current provider billing documentation and an experienced finance/engineering partner before making real purchasing commitments.
