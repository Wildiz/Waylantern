# Learning curriculum: UI Designer

Create consistent visual components with clear states and readable layouts.

[Home](../README.md) / [Curricula](curricula.md) / [Software, interfaces and embedded systems](professions-software.md#roles-in-this-group)

**Target profile:** [UI Designer](professions-software.md#ui-designer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic computer skills
- Access to a design tool

**What you will produce:** A small interface kit and three coherent screens with documented state checks.

**Resource coverage:** 4 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Establish visual hierarchy](#stage-1)
2. [Build reusable components](#stage-2)
3. [Check layout resilience](#stage-3)
4. [Deliver the interface mini-kit](#stage-4)

<a id="stage-1"></a>
## 1. Establish visual hierarchy

**Learn:**

- Typography
- Spacing
- Visual priority

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [GOV.UK Design System](https://github.com/alphagov/govuk-design-system) — intermediate in this topic; free access. [Details](area-design-product.md#resource-govuk-design-system).
- [IBM Carbon Design System](https://github.com/carbon-design-system/carbon) — intermediate in this topic; free access. [Details](area-design-product.md#resource-carbon-design-system).

**Practise:** Arrange a study-dashboard screen around one primary action using component examples as references.

**Advance when:** Explain the intended reading order of title, action and supporting information.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Build reusable components

**Learn:**

- Component anatomy
- Design tokens
- Interaction states

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Penpot](https://github.com/penpot/penpot) — beginner in this topic; freemium access. [Details](area-design-product.md#resource-penpot).
- [IBM Carbon Design System](https://github.com/carbon-design-system/carbon) — intermediate in this topic; free access. [Details](area-design-product.md#resource-carbon-design-system).

**Practise:** Create a button, field and card with shared spacing and visible focus and error states.

**Advance when:** Change one shared token and show consistent updates across component instances.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Check layout resilience

**Learn:**

- Contrast and legibility
- Responsive behavior
- Text expansion

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [GOV.UK Design System](https://github.com/alphagov/govuk-design-system) — intermediate in this topic; free access. [Details](area-design-product.md#resource-govuk-design-system).
- [web.dev Learn](https://web.dev/learn) — beginner in this topic; free access. [Details](area-web.md#resource-web-dev-learn).

**Practise:** Design narrow and wide screens and test long labels and error messages.

**Advance when:** Keep essential text visible and focus and error states distinguishable.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the interface mini-kit

**Learn:**

- Screen consistency
- State specifications
- Developer handover

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Penpot](https://github.com/penpot/penpot) — beginner in this topic; freemium access. [Details](area-design-product.md#resource-penpot).
- [GOV.UK Design System](https://github.com/alphagov/govuk-design-system) — intermediate in this topic; free access. [Details](area-design-product.md#resource-govuk-design-system).

**Practise:** Deliver three connected screens, reusable components and a short interaction-state specification.

**Advance when:** Match each interactive element to a component and identify its empty, focus and error behavior.

## After this recipe

Continue with verified accessibility guidance and implementation collaboration; attractive static screens alone do not establish usability.
