# Editorial practice plan: Mobile App Developer

Build a cross-platform prototype while checking platform assumptions explicitly.

**Target profile:** [Mobile App Developer](professions-software.md#mobile-app-developer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic file skills
- A computer compatible with the chosen Flutter tooling

**What you will produce:** A Flutter habit log with local state and a documented platform test matrix.

**Resource coverage:** 3 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Learn Dart and the toolchain](#stage-1)
2. [Create a reusable screen](#stage-2)
3. [Preserve the habit log](#stage-3)
4. [Deliver the portable mini-app](#stage-4)

<a id="stage-1"></a>
## 1. Learn Dart and the toolchain

**Learn:**

- Variables and functions
- Collections
- Run and debug

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Flutter Getting Started Pathway](https://docs.flutter.dev/learn/pathway) — beginner in this topic; free access. [Details](area-software.md#resource-flutter-getting-started).

**Practise:** Complete introductory Dart material and run a minimal Flutter app.

**Advance when:** Change a value, rerun the app and explain its output.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Create a reusable screen

**Learn:**

- Widgets and layout
- Input state
- Navigation

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Flutter Getting Started Pathway](https://docs.flutter.dev/learn/pathway) — beginner in this topic; free access. [Details](area-software.md#resource-flutter-getting-started).

**Practise:** Build a habit list and an entry form using a reusable row widget.

**Advance when:** Add a habit on a narrow simulated screen without layout overflow.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Preserve the habit log

**Learn:**

- Local persistence
- Lifecycle behavior
- Platform differences

**Resource still needed:** A dedicated Flutter persistence and lifecycle guide is not verified; the setup pathway alone does not establish these details.

**Practise:** Select verified platform-compatible persistence documentation and store records locally.

**Advance when:** Restart the app and recover entries while documenting the storage location for each target.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the portable mini-app

**Learn:**

- Platform test matrix
- Accessible controls
- Reproduction notes

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Flutter Getting Started Pathway](https://docs.flutter.dev/learn/pathway) — beginner in this topic; free access. [Details](area-software.md#resource-flutter-getting-started).

**Practise:** Finish the habit log and record add-and-restart checks on two supported targets where available.

**Advance when:** Label every target tested or untested and reproduce results instead of assuming portability.

## After this recipe

Choose one platform for deeper lifecycle and native-integration study rather than assuming every device behaves identically.
