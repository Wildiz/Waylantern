# Learning curriculum: Technical SEO Specialist

Understand a website technical behaviour and prioritise discoverability and content-structure issues.

[Home](../README.md) / [Curricula](curricula.md) / [Leadership, product and technology relationships](professions-leadership.md#roles-in-this-group)

**Target profile:** [Technical SEO Specialist](professions-leadership.md#technical-seo-specialist)

**Starting point:** Learn the stated foundations first

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Can read basic HTML and understand HTTP requests, responses and status codes.
- Can modify a small website and inspect it using browser developer tools.

**What you will produce:** A reproducible site-audit case with technical evidence, a repaired issue and appropriately limited outcome claims.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Understand the page and its delivery](#stage-1)
2. [Study search-specific mechanisms](#stage-2)

<a id="stage-1"></a>
## 1. Understand the page and its delivery

**Learn:**

- HTML structure
- HTTP responses
- Links and rendering

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [MDN Web Docs](https://developer.mozilla.org/) — all in this topic; free access. [Details](area-web.md#resource-mdn-web-docs).

**Practise:** Create a small local website with three linked pages. Inspect the delivered HTML, status responses, document titles and internal navigation, recording the difference between source and rendered content.

**Advance when:** You can explain how each page is reached and identify its title, response status and link targets.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Study search-specific mechanisms

**Learn:**

- Crawling and indexing
- Canonical signals
- Robots and sitemaps

**Resource still needed:** Current official search-engine SEO guidance has not yet been verified and catalogued; general web documentation does not establish these search-specific rules.

**Practise:** Use verified search-engine documentation when it is added to study robots directives, canonical links and sitemap behaviour. Draft examples for the practice site and separate crawl control from guaranteed index inclusion.

**Advance when:** You can explain what each mechanism signals, a failure it can create and why no single setting guarantees ranking.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Evaluate accessibility and performance evidence

**Learn:**

- Semantic content
- Resource loading
- Measurement context

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [web.dev Learn](https://web.dev/learn) — beginner in this topic; free access. [Details](area-web.md#resource-web-dev-learn).

**Practise:** Use the relevant HTML, performance and accessibility material to inspect the practice site. Record one issue and a reproducible before-and-after technical measure, without equating a tool score with search ranking.

**Advance when:** Your finding includes a repeatable measurement, user impact and a distinction between observed page behaviour and an unmeasured search effect.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Prioritise and review a technical repair

**Learn:**

- Audit evidence
- Impact assumptions
- Validation

**Resource still needed:** A verified technical-SEO curriculum and current search-console learning resources are needed for the remaining search-specific workflow.

**Practise:** Assemble a small audit with affected URLs, evidence, proposed repairs and validation steps. Fix one local issue and record what a real site owner would need to monitor after publication.

**Advance when:** The capstone includes an audit, prioritisation rationale and repair evidence, with no unsupported promise of indexing, traffic or ranking gains.

## After this recipe

Resolve the official-source gap before applying search-specific recommendations to a real site, then build monitored cases with the site owner.
