# Learning curriculum: Computer Technician

Diagnose a fictional computer fault and plan safe physical work without confusing a simulation with repair experience.

[Home](../README.md) / [Curricula](curricula.md) / [Operations, platforms and IT support](professions-operations.md#roles-in-this-group)

**Target profile:** [Computer Technician](professions-operations.md#computer-technician)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Know basic computer controls and files.
- Use authorised training equipment; do not open powered or unfamiliar equipment.

**What you will produce:** A component map, diagnostic evidence and a safe repair/verification plan for a practice computer scenario.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

<a id="stage-1"></a>
## 1. Identify computer components

**Learn:**

- Storage and memory
- Power, peripherals and boot stages

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Professor Messer (CompTIA Network+ and Security+ videos)](https://www.professormesser.com/security-plus/sy0-701/sy0-701-video/sy0-701-comptia-security-plus-course/) — beginner in this topic; free access. [Details](area-devops.md#resource-professor-messer).

**Practise:** Use introductory A+ material to label a computer diagram and connect a boot or peripheral symptom to possible component categories.

**Advance when:** Distinguish a symptom from proof of a failed part and list observations needed before replacing it.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Learn safe physical procedures

**Learn:**

- Power isolation and handling
- Electrostatic and model-specific precautions

**Resource still needed:** No reviewed device-specific repair, battery-safety or electrical-work manual is included in the catalogue.

**Practise:** Write a supervised-work checklist using the exact manufacturer guidance required for a proposed training device.

**Advance when:** Mark any unavailable manufacturer procedure as a blocker rather than inventing disassembly or battery-handling steps.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Separate software from hardware evidence

**Learn:**

- Boot and storage observations
- Reversible diagnostic checks

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Microsoft Windows Troubleshooting Documentation](https://github.com/MicrosoftDocs/SupportArticles-docs/tree/main/support/windows-client) — intermediate in this topic; free access. [Details](area-it-support.md#resource-microsoft-windows-troubleshooting).

**Practise:** Read a relevant Windows diagnostic article and plan non-destructive observations for a fictional boot or device problem.

**Advance when:** The plan identifies what a software log can show and what still requires approved physical diagnostics.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Capstone: prepare a repair handover

**Learn:**

- Part-replacement justification
- Post-work acceptance checks

**Resource still needed:** A complete supervised repair lab and model-specific procedures remain missing; a written plan is not hands-on hardware competence.

**Practise:** Create a fictional repair report with observations, candidate causes, a supervised action plan and checks for boot, data and peripherals.

**Advance when:** The report preserves uncertainty and does not claim a component was repaired or replaced unless that work actually occurred.

## After this recipe

Obtain supervised hands-on training and current manufacturer procedures before repairing customer equipment or handling hazardous components.
