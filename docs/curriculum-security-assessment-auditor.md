# Learning curriculum: Security Assessment Auditor

An assessment recipe for evaluating whether security controls meet agreed criteria and whether evidence supports the conclusion.

[Home](../README.md) / [Curricula](curricula.md) / [Cybersecurity, audit and risk](professions-security.md#roles-in-this-group)

**Target profile:** [Security Assessment Auditor](professions-security.md#security-assessment-auditor)

**Starting point:** Learn the stated foundations first

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic security-control and IT process knowledge.
- Familiarity with evidence handling and professional independence.

**What you will produce:** A mock security assessment containing a test matrix, reproducible checks and a reviewed conclusion with limitations.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Define the assessment boundary](#stage-1)
2. [Design evidence-based assessment procedures](#stage-2)
3. [Test a control and reconcile evidence](#stage-3)
4. [Review and report the assessment](#stage-4)

<a id="stage-1"></a>
## 1. Define the assessment boundary

**Learn:**

- System scope and evidence owners
- Criteria, independence and permitted tests

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Professor Messer (CompTIA Network+ and Security+ videos)](https://www.professormesser.com/security-plus/sy0-701/sy0-701-video/sy0-701-comptia-security-plus-course/) — beginner in this topic; free access. [Details](area-devops.md#resource-professor-messer).

**Practise:** Define a fictional file-sharing system, the control owners and three editorial assessment criteria.

**Advance when:** The assessment plan states which claims will be tested and does not substitute a vulnerability scan for an assurance conclusion.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Design evidence-based assessment procedures

**Learn:**

- Design assessment and operational testing
- Samples, interviews and technical evidence

**Resource still needed:** No particular assessment framework, approved control catalogue or assessor methodology has been verified; the criteria are editorial practice material.

**Practise:** Create test steps for account approvals, access removal and backup recovery using invented records.

**Advance when:** Each procedure states its expected result and the evidence needed to establish it.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Test a control and reconcile evidence

**Learn:**

- Positive and negative test cases
- Exceptions and alternative explanations

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [The Linux Command Line (William Shotts)](https://linuxcommand.org/tlcl.php) — beginner in this topic; free access. [Details](area-software.md#resource-the-linux-command-line).

**Practise:** Test a local practice folder's access restrictions and compare the actual result with a fictional access policy and approval record.

**Advance when:** The workpaper links policy intent, observed behavior and any contradiction, with the account and test date recorded.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Review and report the assessment

**Learn:**

- Conclusion scope and evidence traceability
- Finding validation and follow-up

**Resource still needed:** No formal assurance opinion or assessor qualification is established by this editorial assessment exercise.

**Practise:** Assemble the plan, procedures and workpapers; have a peer dispute one finding and record how you resolve the challenge.

**Advance when:** The conclusion names the criteria and limitations, and every finding can be traced to evidence rather than an unsupported compliance label.

## After this recipe

Obtain supervised experience applying the actual assessment framework required by an engagement and verify its current authoritative criteria.
