# Editorial practice plan: Video Game Designer

Test a small rule system through observable player choices.

**Target profile:** [Video Game Designer](professions-software.md#video-game-designer)

**Starting point:** Start with the basics

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic computer skills
- Ability to record consented playtest observations

**What you will produce:** A short playable rule prototype with a revision log and player feedback.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Define a player experience](#stage-1)

<a id="stage-1"></a>
## 1. Define a player experience

**Learn:**

- Player goals
- Core choices
- Success and failure

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Practice Library](https://github.com/openpracticelibrary/openpracticelibrary) — intermediate in this topic; free access. [Details](area-design-product.md#resource-open-practice-library).

**Resource still needed:** Product-discovery practices help frame questions but no dedicated game-design curriculum is verified.

**Practise:** Write a one-page concept with one main decision and a clear ending.

**Advance when:** Explain how the player choice changes progress.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Make a paper rule prototype

**Learn:**

- Rules and constraints
- Feedback loops
- State changes

**Resource still needed:** A verified source for game mechanics, balancing and paper prototyping is absent; these are editorial exercises.

**Practise:** Create a paper version with counters and record a complete round.

**Advance when:** A second person completes a round from written rules without invented exceptions.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Observe and revise play

**Learn:**

- Playtest questions
- Difficulty and pacing
- Behavioral evidence

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Open Practice Library](https://github.com/openpracticelibrary/openpracticelibrary) — intermediate in this topic; free access. [Details](area-design-product.md#resource-open-practice-library).

**Practise:** Observe two short rounds with consent and change one rule in response to a specific observation.

**Advance when:** Distinguish observations from interpretations and state what the next round should test.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Deliver the design mini-project

**Learn:**

- Rule documentation
- Prototype fidelity
- Revision evidence

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Godot Engine Documentation](https://docs.godotengine.org/en/stable/) — beginner in this topic; free access. [Details](area-games-mobile.md#resource-godot-docs).

**Practise:** Deliver the revised paper game or a minimal digital version with rules and a change rationale.

**Advance when:** A new player finishes a round and the final rules trace to recorded observations.

## After this recipe

Seek dedicated game-design material for progression and balance and learn code only as needed to test the next question.
