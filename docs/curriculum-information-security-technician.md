# Learning curriculum: Information Security Technician

A control-maintenance recipe that connects practical access checks with evidence records and exception handling.

[Home](../README.md) / [Curricula](curricula.md) / [Cybersecurity, audit and risk](professions-security.md#roles-in-this-group)

**Target profile:** [Information Security Technician](professions-security.md#information-security-technician)

**Starting point:** Learn the stated foundations first

**Type:** Waylantern editorial learning recipe. Related official sources are listed separately below.

## Before you start

- Basic administration and file-permission knowledge.
- Ability to maintain a structured checklist.

**What you will produce:** A small control evidence register showing test steps, results, ownership and unresolved exceptions.

**Resource coverage:** 2 of 4 stages have no recorded resource gap. Read the marked gaps before planning your study.

Resource access labels refer to the material or software. Open a resource's details to check prerequisites, hardware, APIs and other running costs before using it.

## Your sequence

1. [Connect information to control needs](#stage-1)
2. [Test access against the intended policy](#stage-2)
3. [Maintain evidence and exceptions](#stage-3)
4. [Handover a control cycle](#stage-4)

<a id="stage-1"></a>
## 1. Connect information to control needs

**Learn:**

- Information classification and ownership
- Access, availability and confidentiality

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [Professor Messer (CompTIA Network+ and Security+ videos)](https://www.professormesser.com/security-plus/sy0-701/sy0-701-video/sy0-701-comptia-security-plus-course/) — beginner in this topic; free access. [Details](area-devops.md#resource-professor-messer).

**Practise:** Invent a small document-sharing service and identify which information needs restricted access and recovery.

**Advance when:** Each information type has an owner and a reason for its proposed controls.

After the checkpoint, [continue to stage 2](#stage-2).

<a id="stage-2"></a>
## 2. Test access against the intended policy

**Learn:**

- Account lifecycle and permissions
- Expected versus observed access

**Study resources** — consult the sections needed for this task; the resources may teach complementary skills:

- [The Linux Command Line (William Shotts)](https://linuxcommand.org/tlcl.php) — beginner in this topic; free access. [Details](area-software.md#resource-the-linux-command-line).

**Practise:** Create a lab folder with two roles and run permitted and denied access checks using harmless sample files.

**Advance when:** Your evidence shows both positive and negative test results, including which account ran each check.

After the checkpoint, [continue to stage 3](#stage-3).

<a id="stage-3"></a>
## 3. Maintain evidence and exceptions

**Learn:**

- Control records and review dates
- Exception ownership and expiration

**Resource still needed:** No verified information-security control register template or specific compliance baseline is supplied; this register is an editorial practice artifact.

**Practise:** Build a register for access reviews, updates and backups; add a deliberately overdue review and an exception with an owner.

**Advance when:** Every record cites test evidence and every exception has a rationale and review condition.

After the checkpoint, [continue to stage 4](#stage-4).

<a id="stage-4"></a>
## 4. Handover a control cycle

**Learn:**

- Retesting and evidence integrity
- Escalation and management reporting

**Resource still needed:** No complete occupational qualification has been verified; this capstone tests disciplined control maintenance rather than certification compliance.

**Practise:** Repeat the checks after removing one account, compare results and prepare a short handover of failures and pending actions.

**Advance when:** A reviewer can trace each reported control status to a dated test and can distinguish untested from failed.

## After this recipe

Ask a control owner or experienced technician to review the register and practise with an organization's actual policies under supervision.
